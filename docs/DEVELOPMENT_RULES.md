# 開発の完了条件

スパゲッティ化の防止と既存コードの治療は、追加機能とは別の後回し作業にしません。すべての変更は次の条件を満たして初めて完了です。

## 依存方向

```text
SwiftUI View
  ↓
WorkspaceStore / 画面用Store（ユースケース調停）
  ↓
HarnessCoreのWorkflow / Builder / Provider
  ↓
ローカルランタイム・ファイルシステム・通信アダプター
```

- Viewから`URLSession`、`Process`、`FileManager.default`を直接使わない。
- `HarnessCore`からSwiftUIやAppKitへ依存しない。
- ランタイム固有形式をStoreやViewで解析しない。
- プロジェクトの状態遷移はCoreのWorkflowまたは`ProjectLibrary`へ置く。
- ファイル書き込みは差分レビューと明示承認を通し、削除・公開・署名・モデル削除など不可逆性の高い操作も承認境界を通す。
- 読み取りと編集で対象ファイルの安全規則を重複させず、共通ポリシーを参照する。
- レビュー後の内容競合を検出し、古い変更案で上書きしない。
- 外部コマンドはProviderへ隔離し、実行ファイルと引数を許可リストで固定する。Viewから任意シェル文字列を渡さない。
- Git復元ポイントはHarness専用refだけを使い、コミット・index・作業ツリーを副作用として変更しない。
- 一時ファイルとGit refは、成功・失敗・取り消し・履歴上限の各経路で寿命を閉じる。
- 手動検証と編集後検証は同じ実行セッションを使い、停止・タイムアウト・結果処理を重複実装しない。
- 編集後検証の失敗では自動復元せず、実行中プロセスを停止してから競合確認付きの復元を人が選べるようにする。
- SwiftPMとXcodeの検証は同じ固定コマンド実行器を使い、Process・一時ログ・停止・出力上限を各Adapterへ複製しない。
- Xcodeの自動検証はschemeのDebug buildに限定し、archive・export・署名・公開を実行経路へ含めない。
- SwiftPM、Xcode、Simulatorは共通の上限付きProcess実行器を使い、一時ログ・停止・タイムアウト処理を複製しない。
- Simulator端末IDはUUIDとして検証し、一覧・起動・起動待ち・画面取得以外の`simctl`操作を許可しない。
- Simulator画像はPNG署名と容量上限を確認し、成功・失敗にかかわらず一時ファイルを削除する。
- 実Simulator統合検査は明示的な環境フラグでだけ起動し、通常のCore検査や利用者環境で端末を自動起動しない。
- Simulator端末選択・旧画像破棄・状態メッセージはSessionへ集約し、Viewで状態を個別更新しない。
- 物理iPhoneの署名付き実行は、自動の署名なしXcode検証と別Provider・別Sessionに分離し、明示確認なしに開始しない。
- 実機経路で許可する操作は端末一覧、署名設定診断、承認後のDebug build、選択端末へのinstall／launchに固定し、archive・export・公開・削除を含めない。
- 端末IDとUDID相当の実行ハンドル、Team ID、Apple Account、実機ビルドログを永続化しない。端末JSON、ログ、DerivedDataは処理終了時に削除する。
- Apple Account認証、端末の「信頼」、Developer Mode確認はユーザー操作として残し、Harnessが資格情報を入力・取得しない。
- 実機統合検査は明示的な環境フラグでだけ実行し、通常のCore検査や画面表示で署名・インストール・起動を始めない。
- ソース変更監視は読み取り専用・項目数上限付きとし、ソース内容やパス一覧を永続化しない。
- 再起動をまたぐ変更判定は決定的な指紋を使い、セッション内Snapshotと変更パスはCoreのMonitorだけが保持する。
- Harness自身の承認済み保存・復元は監視基準を更新し、外部変更通知として重複記録しない。
- 再開チェックポイントへ生ログ、AI指示、ファイル内容を保存せず、再開前に現在のソースを固定コマンドで再検証する。
- 永続化した相対パスを直接編集指示として信用せず、再検証時に既存の安全なファイル境界を通して計画を再生成する。
- 長時間処理のチェックポイントはCoreの状態遷移へ集約し、Viewの表示状態やプロセス参照を永続化しない。
- 中断した検証は途中出力から継続せず、現在のソースへ許可済み固定コマンドを最初から再実行する。
- 中断したAI生成は途中回答や一時ソースコンテキストを保存せず、永続化済み会話から最初から生成し直す。
- AI生成の再実行でユーザー指示や制作項目を重複追加せず、Coreの既存状態遷移を再利用する。
- 継続指示は語の部分一致で判断せず、否定・質問・具体的な追加依頼を原文のまま扱う。受付直後のAI応答記録を未完了の制作候補へ混ぜない。
- AI応答の追跡記録と実制作項目を明示的に区別し、応答完了だけで制作項目を完了にしない。継続時は未編集の応答記録だけを再利用し、受付が返したIDを生成・停止・復旧へ一貫して渡す。
- 中断した処理のチェックポイントを新規会話で上書きしない。受付できない入力は消さず、既存の再開・破棄導線を案内する。
- ストリームのループ内だけでなく、受信終了後・非同期の提案検証後にもキャンセルを確認してから成功を確定する。キャンセルによる正常EOFを応答完成・計画完成として保存しない。
- 継続返答の重複判定はCoreの純粋な規則へ分離する。前のローカル回答をsystem命令へ昇格させず、外部レビューや別の具体指示の回答を比較元にしない。数字・句読点・コード内空白など意味のある違いを消して同文と判定しない。
- 同文の自動再検討は同じ受付内で1回までとし、ユーザー指示・制作サイクル・作業項目を増やさない。再検討中も停止でき、失敗・停止・再度の同文では候補を会話へ保存しない。
- 会話の文脈選択はユーザー発話とAI／外部参考の容量を分け、長いAI回答だけで短い訂正・禁止事項を押し出さない。選択はプロジェクト内で完結し、順序・原文・出所を保存したまま、省略を明示する。
- 提案・読み取った実装・実行／検証の証拠を区別する。ソース内容をsystem命令へ入れず、容量制限後も引用の開始・終了境界を保つ。過去の成功・進捗表示だけで新しい案を実装済み・検証済みにしない。
- モデルが内部の参考見出しを返した場合は、Coreの共有された既知の先頭ラベルだけを表示・保存前に除外する。普通の本文・引用・コードを一括置換せず、途中受信・停止・空回答・同文比較と既存履歴の保存を保護する。
- モデル取得はワークスペース単位の専用チェックポイントで扱い、コマンド出力・一時ファイル・モデル断片・ダウンロード済みバイト列を保存しない。
- モデル取得の停止はUI状態だけでなく子プロセスへキャンセルを伝え、再開は同じモデルIDとランタイムの固定引数を再実行する。
- モデル取得の生ログはGUIへ渡さず、既知の取得率・検証・保存工程だけをCoreの短い進捗イベントへ変換する。進捗イベントは永続化しない。
- モデル適合性のメモリ・ディスク余裕はCoreの単一ポリシーで判定し、Viewへ閾値を重複させない。実機容量は永続化せず、空き容量不足では取得プロセスを開始しない。
- リモート待受は初期状態で無効とし、暗号化必須・一時ペアリングコード・通信版・容量上限・重複拒否・受付応答を共通境界にする。コード、端末名、受信IDは永続化しない。
- リモート指示も通常指示と同じ推論Workflowへ渡し、出所を履歴へ保存する。別の自動書き込み経路を作らない。
- プロジェクト雛形は固定テンプレートを新規ディレクトリだけへ排他的に作成し、既存先を上書きしない。途中失敗の後始末はその処理が作成したルートに限定する。
- ワークスペース保存前に直前の有効世代を別ファイルへ保持し、主ファイル破損時は復元元をUIへ明示する。
- 復元可能な世代が一つもない場合は既存の破損ファイルを上書きせず、保存エラーとして扱う。
- Releaseアプリは空の一時領域から共通パッケージャで組み立て、旧バンドルの複製や手作業の版番号変更を行わない。
- 配布ZIPは再展開後の署名と版番号を検証し、同一バージョンの既存成果物を自動上書きしない。
- Universal配布物はarm64とx86_64を同じXcode SDK・最小OSで別々にビルドし、結合前後とZIP再展開後に両sliceを検証する。
- Release工程では実行ファイルとアイコン生成を同じフルXcode toolchainへ固定し、システムのCommand Line Tools設定へ依存しない。
- GUIスモーク検査対象の主要導線は意味的アクセシビリティIDを共通カタログから参照し、Viewへ生文字列を散在させない。
- ナビゲーションや主要シートのID欠落は構造検査で失敗させ、画面順序・要素番号・表示文言だけに依存するテストを作らない。
- 制作ループの状態遷移はCoreの単一Workflowへ集約し、各Viewや非同期Sessionにフェーズ判断を重複させない。
- 長時間の連続制作は1回に一つの実制作項目をUUIDで固定し、既存の差分承認・固定検証・完了承認を再利用する。別の書込経路やView内の独自状態機械を作らない。
- 連続制作は同じ検証失敗2回と確認なしの連続サイクル上限で停止する。台帳には項目ID・イベント・時刻だけを上限付きで保存し、AI指示、ソース、絶対パス、生ログを含めない。
- 連続制作の読込復帰は固定項目IDと台帳証拠をCoreで照合する。不整合を検証済みや完了へ進めず、再検証または計画確認へ戻す。正常な復帰でサイクル数や承認数を増やさない。
- 検証失敗はCoreで実装、テスト挙動、toolchain、Simulator、署名、依存関係、資源不足、混在、判定不能へ分類する。実装原因は接続ルート内の安全な既存ファイルへ正規化できた診断だけを根拠にし、生の`.swift: error:`文字列を権限にしない。環境原因、混在、判定不能ではコード修正・修正計画・AI再計画を始めず、同じ検証の再確認へ戻す。ViewやCoordinatorに独自markerを複製しない。
- 検証後のAI再計画はコード変更を許可できる失敗時だけ行い、生の診断文やログを渡さない。既存項目のUUID・状態・名前・完成条件はAIに書き換えさせず、並べ替えと上限付き追加だけを提案として扱う。
- 再計画案は未確定点を独立表示し、明示採用まで永続化・適用しない。作成後に計画が変わった案をfingerprintで拒否し、採用後は古い検証証拠を失効させる。
- 再計画の未完了項目は既存と新規を合わせて常に12件以下にする。追加枠は最大3件と残り枠の小さい方とし、prompt、Parser、採用Workflowの各境界で同じ上限を検査する。
- ローカルAIのHTTP通信はディスクキャッシュとCookieを使わない一時セッションに限定し、共有セッションへ戻さない。
- 実モデルを使う制作E2Eは明示環境フラグ時だけ実行し、使い捨てソース以外のワークスペースを読まない。結果にはモデル名、検証種別・成否・終了コード・時間、復帰段階、最小台帳イベントだけを残し、生成ソース、指示、生ログ、一時パスを出力しない。
- プロジェクトの工程・百分率は確認済みマイルストーンからCoreで更新し、ViewやAdapterへ進捗計算を重複させない。完成は未完了の実制作項目・中断作業・修正待ち・未反映成果物がなく、現在のソースの最終検証に成功した場合だけ許可する。制作内容の変更後は古い検証成功を失効させ、完成操作で作業項目を一括完了へ書き換えない。旧完了データの工程と100%は読込時に正規化しても、残された作業証拠は保持する。
- 成果物や検証ログを外部AIへ渡す場合は、容量上限・パス匿名化・資格情報らしき内容の除外・送信前プレビュー・明示操作を必須にする。
- 外部AIのWeb画面をアクセシビリティ操作で自動送信せず、手動連携と正式API Providerを交換可能な境界へ分ける。
- 操作要素を含むSwiftUIコンテナへアクセシビリティIDを付けず、画面IDは葉要素、操作IDは対象コントロールへ直接付けて伝播上書きを防ぐ。
- GUI fixtureのワークスペース差替えは、OS一時領域内の絶対`workspace.json`だけに限定する。fixtureのソースルートとHarnessワークスペースは兄弟ディレクトリへ分け、保存JSONをソース監視へ入れない。通常起動やユーザーフォルダをfixtureとして受理せず、検査データを保存済みワークスペースから作らない。
- 外部AIの回答はローカルモデル応答と同一視せず出所を保存し、次回推論では容量を再制限した未信頼の引用資料として隔離する。
- 非同期AI生成は開始・成功・停止・失敗をCore Workflowへ集約し、異常終了後に生成中フェーズだけが残らない最小チェックポイントを持つ。
- 新規ファイルは更新操作と明示的に区別し、既存ディレクトリ・許可形式・非機密名・非シンボリックリンクをCoreで検査する。同名対象は保存直前にも排他的に拒否し、別経路で上書きしない。
- 新規作成も既存編集と同じ差分確認・明示承認・保存後検証を通し、Git復元ポイントを空ファイル更新として偽装しない。
- 複数ファイル計画も一括書き込みAPIを持たず、CoreのCoordinatorが選ぶ現在対象1件だけを既存の差分承認境界へ渡す。
- AI生成の成果物計画は件数・形式・相対パス・重複・既存対象・親フォルダを開始前に検査し、途中応答や生成ファイル内容を永続化しない。
- 用語解説は検出・引用プロンプト・推論・表示寿命を分離し、本文全体やソースを追加収集しない。結果は上限付きメモリキャッシュだけに保持し、制作指示・検証証拠・永続会話へ混ぜない。
- ホバーは待機時間を置き、移動・画面離脱・モデル変更時に取消を伝播する。制作や操作が進行中なら新規解説の推論を始めない。
- ホバー表示前の離脱は即時取消とし、表示後のポップアップ移動用猶予と混ぜない。複数の追跡領域の入退場順序を前提にせず、状態機械のテストで古い回答の混入と誤った閉鎖を防ぐ。
- 頼み方の候補は任意の会話支援であり、選択だけで送信・操作・検証成功にしない。入力中の本人の文章を確認なしで上書きせず、送信時は自由入力と同じ指示受付・承認境界を通す。
- 候補生成の引用・件数・文字数・待ち時間をCoreで制限し、失敗・停止・古い生成世代を排除する。会話・モデル・プロジェクト変更で破棄し、未選択の候補や恒久的な好みとして永続化しない。
- 理由説明は口調調整から分離し、最新のユーザー原文・読めたソース・未確認の区別に結びつける。モデルの一般知識で未調査の機器制限や未測定の数値を補わない。
- 回答直前の条件再掲は同じプロジェクトの本当のユーザー発話だけを固定件数・文字数で扱う。AI回答、外部レビュー、別プロジェクト、要約した恒久的な好みを混ぜず、実行権限にしない。
- 推論時間の診断値は単調時計で要求単位に測り、回答が出始めるまでと受信を分ける。本文・入力・モデルID・壁時計を診断値へ保存せず、失敗・停止・古い回答へ表示しない。
- 推論入力の内訳は役割と共有された引用境界から文字数だけを集計する。本文、モデルID、ファイル名を診断値へ複製せず、アプリ終了時に破棄する。
- ソース引用と外部レビュー引用の分類はCoreの完全な開始・終了マーカーを共用し、本文中にマーカー名が現れただけでは引用として扱わない。Viewや各Prompt Builderへ判定規則を複製しない。
- 会話用ソースの省略は、最新の本人指示が既存返答の言い直しを明示し、コード・実装・ファイル・build/testなどの確認を求めない場合だけに限定する。継続指示、普通の制作相談、判断不能時は全ソースへ戻す。
- ファイルを絞る時は本人が書いたASCII名と収集済み相対パスの実一致を必須にし、同じ識別子を参照するファイルを収集順のまま上限付きで選ぶ。未知名、一般語、選別効果がない場合は全ソースを維持する。
- ソース選択は収集・機密除外・引用境界を変更せず、選択語やソース本文を新しい永続状態へ保存しない。GUIには選んだ件数または省略理由だけを表示する。
- 文数検査は最新の本当のユーザー原文にある1〜10文の最後の有効な明示指定だけを対象にする。取り消した指定、範囲・上限・曖昧な短さを厳密指定に変えず、未達時は意味と未確認条件を保持した再検討を1回だけ行う。機械的な文の切断や未達回答の完成保存は行わない。
- 同文検査は最新の本人指示が明示的に言い直しを求め、直前の非空回答が同じローカルモデル由来である時だけ行う。「同じ回答をもう一度」「言い換えないで」のような反対意図は除外する。
- 回答同一性はCoreの共通規則で外側の空白と改行コードだけを正規化し、数字・句読点・大小文字・コード内空白を意味のある差として保持する。継続回答と明示的な言い直しで比較規則を複製しない。
- 明示的な言い直しが同文なら未確定回答を履歴へ保存せず、意味・不確かさ・文数・長さを保った別表現を1回だけ求める。文数の再検査も同じ最終回答へ適用し、再試行回数を重ねず、未達なら完成保存しない。
- 言い直し検査は新しい永続状態や実行権限を作らず、再検討用の未確定回答も文字数上限を設ける。

## ファイルと責務

- Swiftファイルは原則350行以内。超える前に機能境界で分割する。
- 1ファイルへ型を寄せ集めず、変更理由が同じ型だけを置く。
- 分割は単なる行数移動にせず、通信・解析・状態遷移・表示などの責務で行う。
- 同じ上限値や判断規則をUIとCoreへ重複記述しない。
- 通常UIのフォントは`HarnessTypography`の意味的トークンを使い、Viewへフォント名やサイズを散在させない。
- 等幅フォントはコード・差分・ログなど桁揃えが機能要件となる表示だけに限定する。
- 新しい外部依存は、既存のFoundation / SwiftUIで解決できない理由を明確にする。

## 画像コミュニケーション

- 画像理解、決定論的画像処理、画像生成、生成編集を別責務・別能力として扱う。テキスト会話対応を、画像が見える・作れる・編集できる証拠にしない。
- Viewは画像byteの読込、decode、metadata除去、縮小、base64化、モデル通信、保存を行わない。選択・drop・paste・preview・取消だけをApp層sessionへ渡す。
- workspace JSONへ画像本文、base64、EXIF、絶対パスを保存しない。管理領域の相対ID、SHA-256、形式、寸法、由来、親revisionだけを必要最小限に保持する。
- 原画を上書きしない。crop・余白・resize・toneは再現可能なrecipeとして新revisionを作り、生成編集は最大1工程かつ最後に限定する。
- 画像内の文字・QR・UI指示は未信頼の観察対象であり、ユーザー指示、承認、Computer操作、ファイル変更、外部送信の権限にしない。
- スクリーンショットの文字認識は端末内OCRをVLMと併用し、文字・信頼度・位置を上限付きの一時情報として扱う。OCR本文をworkspaceへ保存せず、低信頼文字を確定事実にしない。
- 画像の読込、観察、編集、生成、検査は別フェーズで表示し、停止を伝播する。途中画像や未採用候補を完成成果物へ昇格させない。
- Apple向けアイコンは原寸だけで評価せず、小サイズ、system mask、appearance、対象プラットフォームの一貫性を人が比較して採用する。

## 音声コミュニケーション

- 音声は入力・出力interfaceであり、制作判断、プロジェクト状態、権限、Runtime、検証の正本にしない。
- volatileな文字起こしは表示だけに使い、送信しない。Push-to-talkのfinalized結果は編集可能な下書きへ置く。明示的に開始した会話モードだけは、VADで確定したfinalized結果を通常会話へ自動送信できる。
- マイク音声はSpeechAnalyzerへの一時streamとしてだけ扱い、録音ファイル、音声byte、transcriptをworkspaceへ自動保存しない。既存の手入力は音声確定時にも上書きせず追加する。
- マイク、VAD、言語資産、audio format変換はApp Adapter、Push-to-talkと会話turnの世代管理・取消は別Session、文字連結・権限・読み上げ要約はCoreへ分ける。ViewからSpeech／AVFoundationを直接呼ばない。
- SpeechAnalyzerの端末内経路はマイク許可だけを文脈内で要求する。未確認時だけOS確認を出し、許可済み、拒否済み、端末管理の制限を別状態にする。Appleサーバーへ送るAPIを導入しない限り、サーバー音声認識用の許可を追加しない。
- AVAudioEngineのtap callbackはリアルタイムqueueで動くため、`@MainActor`のclosure、Session、Viewを直接捕捉しない。SendableなBridge内でbuffer変換とstream投入を完結し、失敗の文字列だけを明示的にMainActorへ戻す。専用queueからtap blockを呼ぶ回帰検査を必須にする。
- discussion、idea、proposal、command、cancel、approve、statusの分類は候補であり、権限ではない。音声の承認だけでファイル変更、Computer操作、外部送信を許可しない。
- 「止めて」で読み上げは即停止してよいが、進行中作業には既存checkpointへの取消要求を出し、安全な境界で止める。音声停止を自動rollbackと同一視しない。
- 音声会話、local STT、TTS、Voice Capsule、Engine Adapterを別責務にする。Viewは録音byteの保存、モデル呼出し、speaker embedding生成を行わない。
- 読み上げ中のマイク監視はvoice processingをbest effortで有効にし、再生文に含まれるechoと短い相づちを捨てる。確定した訂正・十分な発話だけで未再生音声を破棄し、次turnへ移る。進行中作業の取消、rollback、権限承認へ連動させない。
- 自動割り込みは画面上の明示操作を置き換えない。雑音、echo cancellation失敗、誤認識時にもユーザーが読み上げ停止と会話終了を選べる導線を保つ。
- 会話turnの終了は固定無音値だけで決めず、確定transcriptの末尾が明示終了、文末、言いよどみ、未完了接続のどれかをCoreで判定する。値は実マイク評価で調整し、ViewやAdapterへ散在させない。
- 音声診断は準備・確定・AI回答・読み上げの時間、読み上げ文字数、成功段階だけをSession内に保持する。録音、transcript、回答本文、プロジェクトIDと結合せず、Codableやworkspace保存対象にしない。
- Voice Capsuleの可搬manifestへEngine名、speaker embedding、生成cacheを入れない。参照音声、transcript、alignmentは管理資産とし、workspace JSONにはcontent hashと最小metadataだけを持つ。
- preset以外のVoice Capsuleには同意証拠を必須とする。外部書出し、他人の声、共有は話者照合・権利・provenanceが完成するまで実装しない。
- 会話の頭脳モデル、TTS Engine、選択可能なVoice Model Profile、本人Voice Capsuleを別責務にする。頭脳モデルの導入・削除UIへTTS固有状態を混ぜない。
- 標準音声はモデル重みではなく、利用可能な端末内voiceへの参照、速度、pitch、会話styleを持つ。利用不能時は言語と品質でfallbackし、特定のOS音声名を必須にしない。
- システム音声の追加ではidentifierだけを上限付きで保存する。ViewはAVSpeechの列挙・解決、UserDefaults書込、読み上げを行わない。
- 任意の音声名・外部manifestをsystem promptへ挿入しない。標準profileの固定styleだけを音声会話へ反映し、人物・俳優・作品キャラクターの模倣を指示しない。
- 試聴は明示操作で開始し、同じ画面で停止できること。会話中のSpeakerと試聴Speakerは寿命を分け、画面移動時に試聴を止める。
- MP3 Voice Capsule取込はApp Adapterで実形式・通常ファイル・50MB・3〜30秒を検査し、24kHz monoへ変換する。Viewは音声byte、hash、ファイル保存を扱わない。
- 取込元MP3は複製せず、正規化参照音声、任意transcript、manifestだけを`Application Support/Harness/VoiceCapsules`へ保存する。fixture起動ではfixture隣接領域へ隔離する。
- ファイルを所持している事実を本人同意や権利帰属の証明にしない。private on-device利用でも明示attestationを必須とし、外部共有はspeaker verification済みの外部確認が整うまで開放しない。
- Voice Capsule保存完了と、TTS Engineが生成に利用可能な状態を分ける。Adapter未導入時に選択・試聴・「使用可能」を表示しない。
- 頭脳用LLMとTTS Engineのruntime、model、導入状態を混ぜない。TTS固有Python依存をシステムPythonやOllama／LM Studioへ追加しない。
- 合成本文、参照transcript、音声pathを外部コマンドの生ログや引数へ入れない。privateな使い捨てdirectory、上限付き実行器、offline環境、終了時削除を共通境界にする。
- Voice Capsuleは保存時と合成直前の両方でmanifest・音声・transcriptのhashを照合する。初期の高品質clone経路は正確なtranscriptなしに起動しない。
- Engineのfile readinessを品質合格や会話利用可能と同一視しない。実モデルの速度・RAM・日本語品質・失敗fallbackを測るまで選択を開放しない。
- SwiftPM resource bundleへ置く音声workerはRelease ZIPの再展開後にも存在することをパッケージ工程で検査する。
- 後から追加するVoice Capsule transcriptはCoreで空欄・文字数を検査し、音声・ID・同意を変えない。既存transcriptを同じ追記APIで上書きせず、編集はrevision比較と明示確認を持つ別操作にする。

## 会話品質の改修

先行研究を採用するときは一次資料・公開日・対象条件・Harnessへの適用範囲を記録します。学術プレプリント、開発事例、自分たちの測定を区別し、論文の改善率をそのまま製品の改善率にしません。

原文の訂正、継続、曖昧な同意、提案と実装の混同を含む同じ評価ケースで、改修前後の出力・待ち時間・確認回数を比較します。意味の品質をキーワード一致だけで合格にせず、モデルを追加する場合は誤判定と利用者の負担も測ります。実モデル検査は合成データによる明示実行に分け、通常の回帰検査へネットワークやモデル起動を混ぜません。
