# Local Factory for Mac

手元の Mac だけで動く、会話でソフトウェアを作る・直すためのアプリです。
チャットで「ここを直して」と頼むと、ローカルの AI が修正案を作り、**ビルドとテストを隔離環境で通したものだけ**を
会話の中のカードとして見せます。承認するまでプロジェクトは変わりません。

A local-first Mac app for building and fixing software through conversation. Changes are proposed by a local model,
built and tested in an OS sandbox, and shown as a reviewable card in the chat; nothing touches your project until you
approve it. No cloud API is required.

## できること

- **チャットで修正を指示**:Swift パッケージを接続したプロジェクトで「〜を直して」と書くと、計画 → 修正 → ビルド →
  テストを手元で実行し、変更ファイル・テスト結果・要確認の点をカードで表示。適用・差分の確認・取り消しができます。
  続けて指示すると、前の修正案に重ねて作り直します。
- **写真から伝える**:写真ライブラリ、ファイル、貼り付け、iPhone での撮影(連係カメラ)から画像を添付できます。
  画像の文字は端末内で読み取って指示に添えます。
- **要確認の表示**:テストに通っても誤りが残りやすい修正(最初の実装が失敗して修復した、条件が多い、境界の条件が多い、
  同じ古い処理がほかにも残っている など)に印を付け、どこを確かめるべきかを示します。
- **「この動きで合っていますか？」**:印の付いた修正では、依頼の境目にあたる場面(例:合計がちょうど 5,000 円の注文)を
  修正後と変更前のコードで実際に動かし、結果を日本語で見せます。「違う」を押すと、依頼の別の読み方を直し方の候補として
  示し、選ぶとそのまま続きの指示になります。
- **検査役**:印の付いた修正では、別の呼び出しが依頼から独立にテストを書いて確かめます。落ちたテストは期待値を伏せて
  計算し直させ、依頼から計算した値と一致したときだけ「確かめてほしい点」として値を添えて示します。
- **プロジェクトの約束ごと**:例が違ったときに選んだ直し方や書いた正しい動きを覚え、次からの修正の指示に添えます。
  その場面は、確かめたうえでプロジェクトのテストとして追加でき、以後の修正で同じ誤りが戻ると止まります。

## ファイル作業(チャットから)

- **読む**:PDF・Word・Excel・CSV を添付して、要約・質問・比較。
- **一括リネーム**:フォルダを添付して「撮影日_連番にして」。AI は名前の付け方の規則だけを書き、全件の変更前 → 変更後の表を
  アプリが作って見せます。重複や使えない名前は反映前に止め、取り消しもできます。
- **Excel**:セルの書き換え(書式を残して「〜_編集済み.xlsx」に書き出し)と、集計・解析(AI が SQL を書き、
  [DuckDB](https://duckdb.org) が計算。表を読み込んだあとはファイルの読み書きを封じます)。DuckDB は `brew install duckdb` で入ります。
- **PDF**:結合・抜き出し・削除・並べ替え・回転・透かし・注釈・フォーム記入(macOS 標準の PDFKit)。
- **Word**:書式を残して本文の文章を書き換え。
- どれも元のファイルは書き換えず、新しいファイルに書き出します。画面に出す数や名前は機械が出したものです。
- Excel と Word は、ファイルの中の XML のうち編集した部分だけを書き換えます。書き出しのたびに、編集していない部分
  (図形・テキストボックス・画像・書式・ヘッダー・グラフなど)が元のファイルと 1 バイトも違わないことを確かめ、違えば中止します。
  Excel の共有数式・配列数式の元のセルは書き換えず、数式のあるブックは開いたときに再計算させます。
  ただし、図形やテキストボックスの中の文字、複雑な数式そのものを AI に直させることはまだできません(本文の文章とセルの値・数式のみ)。

## 用途ごとのモデル

入力欄で「会話 / 文章を書く / 画像を作る」を切り替えられます。文章や画像に使うモデルは、手元の設定ファイル
(`config/purpose-models.json` または `~/Library/Application Support/Harness/purpose-models.json`)に書いて、
「AIモデル」画面で選びます。画像は [mflux](https://github.com/filipstrand/mflux) などのコマンドで作り、その間は言語モデルを
メモリから外します。文章と画像の指示は、未成年を性的に描く内容などを言葉の組み合わせで止めます。
- **音声での会話と入力**、プロジェクトごとの会話の記録。

## 画面の操作と補助の Mac

- **アプリを一手ずつ操作(試験):** 前面のアプリの画面の部品を読み、AI が一手ずつ操作します。部品の一覧が少ないアプリでは窓の画像を読みます(27B に同じモデルの画像の部品を付けて使用)。送信・購入・削除・公開・ログイン・同意の前と、中身のある欄への入力の前には毎回確認し、パスワードは入力しません。操作は日ごとの記録に残ります。macOS のアクセシビリティの許可が必要です。
- **補助の Mac(任意):** Thunderbolt でつないだもう 1 台の Mac の小さなモデル(8B)に、形の決まった軽い仕事(Word・Excel の直しの指示、集計の SQL、PDF の操作、名前の付け方の規則)を任せられます。SSH の専用の鍵で入り、補助の Mac のモデルはその Mac の中だけで待ち受けます(ネットワークには公開しません)。つながっていないときはこの Mac で動きます。M4 の MacBook Air での実測: 軽い仕事 5 件が 23.7 秒(この Mac の 27B で 35.7 秒)、重い仕事と同時に流すと全体が 30% 短縮。27B を補助の Mac で動かす・1 つのモデルを 2 台に分けるのは、遅くなるので行いません。

## 仕組み(ハーネス)

修正は 1 回の AI の応答で決めず、次の段階を順に通します。

1. 依頼を条項に分け、計画を立てる(どの条項をどのファイルで満たすか)
2. 編集案を作る(既存の行を正確に指定して書き換える形式)
3. 隔離環境でビルドし、失敗したらエラーを見せて修復する
4. 既存のテスト(保護され、AI には中身を見せない)を実行する
5. 置き換えた古い処理がほかのファイルに残っていないかを機械的に調べ、残っていれば追加で直す
6. 誤りが残りやすい修正では、検査役の確かめと、具体例による確認をユーザーに出す
7. テストに通っても「完成」とは言わず、最終確認は人が行う

## 動作条件

- Apple シリコンの Mac、macOS 14 以降(OS 内蔵モデルを使う意図の判定は macOS 26 以降)
- Xcode(ビルドとテストに使います)
- メモリ 32GB 以上を推奨(27B 級のモデルを使う場合)
- ローカルモデル(どれか 1 つ)
  - [Ollama](https://ollama.com):例 `ollama pull hf.co/lmstudio-community/Qwen3.8-27B-GGUF:Q4_K_M`
  - [Backburner](https://github.com/StayLameBro/backburner)(llama.cpp ベースの高速化。導入済みならアプリが自動で起動します)
  - LM Studio など OpenAI 互換のサーバー

## ビルドと起動

```bash
swift build
swift build --product HarnessKernelPilot   # 隔離環境での実行に使う補助プログラム
.build/debug/Harness
```

## 計測

検証付きの修正がどれだけ正しく動くかを、課題集で計測できます。
`eval/sample-suite` に公開用の見本(3 件)があります。詳しくは [eval/sample-suite/README.md](eval/sample-suite/README.md)。

- **成功**:見えるテストと、AI に見せない隠しテストの両方に合格
- **偽成功**:見えるテストには合格したが、隠しテストで失敗(「できた」と言っているのに誤りが残る状態)

開発中の非公開の課題集(Swift の小さなパッケージ 22〜32 件)では、Qwen3.8-27B で
成功 15〜17/22・23〜25/32 程度、偽成功は 1 割強残っています(2026-10 時点)。
検査役(小さな書式でテストを書かせ、期待値を伏せて計算し直す)の警告は 112 件の評価で 8 件すべてが本物の誤りでしたが、
偽成功のうち検査役が見つけられるのは 3 割ほどです。残りは具体例の確認と人の確認で補う設計にしています。

## 安全のための約束

- AI が書いたコードのビルドとテストは、ネットワークを遮断した OS の隔離環境で実行します(Swift パッケージの場合)。
  Xcode プロジェクト(.xcodeproj)のビルドとテストも OS の隔離の中で行い、通信を遮断し、書き込みをその回の作業フォルダと
  macOS の一時・キャッシュの場所に限ります(システムのサービスと Simulator を使うため、読み取りは Swift パッケージより広く許しています)。
  Swift パッケージの取得だけは、隔離の前に通信ありで行います。
- 修正はユーザーが「適用する」を押すまでプロジェクトに書き込みません。適用は全ファイルまとめて行い、途中で失敗したら
  元に戻します。取り消しもできます。戻せないファイルがあれば(適用後に手で編集した場合など)、そのファイル名を伝え、
  変更を「適用済み」のまま残します。「元に戻しました」と表示するのは、すべて戻せたときだけです。
- 受け入れテストは保護され、AI が書き換えることはできません。
- Backburner を使う場合、モデルを GPU メモリに保持するための設定変更で、macOS の管理者パスワードの確認が出ることが
  あります(アプリはパスワードを保存しません)。
- 送信先は手元のモデルだけです。外部のサービスへコードや会話を送りません。
